01 · modelo mental

Git guarda snapshots locais.

Git não é GitHub. Git registra histórico no computador; GitHub é uma hospedagem e camada de colaboração.

Editarworking tree
git addstaging area
git commithistórico local
git pushenviar
git pullreceber + integrar

Três lugares

Working tree: arquivos editáveis.

Staging: conteúdo selecionado para próximo commit.

Repository: snapshots já salvos em .git.

Três perguntas

git status — onde estou?

git diff — o que mudou?

git diff --staged — o que será salvo?

Exercício relâmpago

Explique para colega por que git add não envia código para GitHub.

Resposta: git add só move conteúdo para staging local. git commit salva localmente. git push envia ao remote.
Snapshot, não “salvamento mágico”2 / 14

03 · commits

Commit é checkpoint.

Commit pequeno cria recuperação, revisão e contexto. Staging permite escolher exatamente o que entra.

Rotina

daily loop
git status
git diff
git add README.md
git diff --staged
git commit -m 'Explain README'

Teste de compreensão

Edite README.md e crie notes.md. Stage apenas README. Mostre diferenças staged e unstaged antes de commit.

mensagem: verbo + mudança

não: changes / stuff

Inspecione antes de salvar4 / 14

04 · branches

Branch isola trabalho.

Branch é nome móvel apontando para commit. Confirme branch atual antes de mergear.

feature workflow
git switch main
git switch -c feature/demo
# editar e testar
git add README.md
git commit -m 'Add demo feature'
git switch main
git merge feature/demo
git branch -d feature/demo
Destino de merge = branch atual5 / 14

05 · comparar

Diff responde “o que mudou?”.

Compare working tree, staging, commits, arquivos específicos e estatísticas.

Mapa

git diff: não staged.

git diff --staged: staged.

git diff HEAD: tudo desde último commit.

Referências

HEAD = commit atual.

HEAD~1 = um commit antes.

main = ponta local da branch.

Leia patch, não só nome de arquivo6 / 14

06 · merge e conflito

Conflito é pausa para decisão humana.

Git não escolhe quando duas branches alteram mesmo trecho de formas incompatíveis.

Resolver

  1. git status
  2. abrir arquivo
  3. escolher texto final
  4. remover marcadores
  5. git add arquivo
  6. git commit

Abandonar merge

Se decisão não está pronta:

abort
git merge --abort

não apague arquivo para escapar

Conflito resolvido só após add + commit7 / 14

07 · pausa temporária

Stash estaciona trabalho.

Use quando precisa trocar branch com mudanças incompletas. Stash não substitui commit permanente.

stash lifecycle
git stash
git stash list
git stash apply
git stash pop
git stash drop
Exercício

Edite README sem commit. Rode git stash. Troque branch. Volte. Restaure com git stash apply. Compare apply e pop.

Resultado: stash limpa working tree e guarda entrada. apply restaura e mantém entrada na lista. pop restaura e remove entrada se aplicação concluir. drop remove entrada sem restaurar.
Antes de stash: status. Depois: status.8 / 14

08 · desfazer com segurança

Onde está o erro?

Escolha comando pela camada: working tree, staging ou commit. Comandos destrutivos ficam em repositório descartável.

EstadoComandoEfeito
Editado, não stagedgit restore arquivodescarta edição local
Staged, não commitgit restore --staged arquivomantém edição, tira do próximo commit
Commit compartilhadogit revert commitcria novo commit inverso
Merge em andamentogit merge --abortretorna antes do merge
instrutor-led git reset --hard, git clean e force push podem apagar ou reescrever trabalho. Primeiro faça checkpoint ou use clone descartável.
Commits ajudam recuperar; uncommitted pode sumir9 / 14

09 · arqueologia

Histórico conta história.

Use log para descobrir quando, onde e quem mudou algo. Use reflog como trilha local de recuperação.

history
git log --oneline --graph --decorate --all
git log --follow README.md
git blame README.md
Não memorize hash: use referências10 / 14

10 · remote

Compartilhar = push. Receber = fetch/pull.

Remote pode ser GitHub ou um bare repository local. Aula usa local para evitar credencial e internet.

remote lab
cd ..
git init --bare class-git-remote.git
git --git-dir=class-git-remote.git symbolic-ref HEAD refs/heads/main
cd class-git-demo
git remote add origin ../class-git-remote.git
git push -u origin main

fetch

Baixa informação e atualiza referências como origin/main. Não troca seus arquivos atuais.

pull

Busca e integra. Neste curso, prefira git pull --ff-only quando local não divergiu.

Commit antes de pull11 / 14

11 · configuração

Configuração evita atrito.

Identidade vai no commit. Aliases reduzem digitação. Arquivos de configuração têm escopos diferentes.

Setup inicial

identity
git config --global user.name 'Seu Nome'
git config --global user.email 'voce@example.com'

Arquivos importantes

.git/config — repo atual.

~/.gitconfig — global.

.gitignore — padrões compartilhados de arquivos ignorados.

Config global não é segredo12 / 14

13 · takeaway

Status. Diff. Add. Commit.

Depois: branch, merge, push. Quando algo der errado: status primeiro.

takeaway card
git status
git diff
git add README.md
git diff --staged
git commit -m 'Descrever mudança'
git switch -c feature/nome
git switch main
git merge feature/nome
git push -u origin feature/nome

Take-home

Crie projeto pequeno, faça 2 commits, use .gitignore, crie feature branch, faça merge, entregue log + status limpo.

Próxima aula

Rebase, cherry-pick, tags, bisect, hooks e worktrees só depois de dominar estados e recuperação básica.

Git não exige memória perfeita. Exige inspeção disciplinada.
