01 / framework

A repeatable interview loop

Strong system design answers expose assumptions before they name Azure services.

Clarifyusers, features, SLO
EstimateRPS, storage, growth
Drawrequest + data path
Stressfailure + hot keys
Operatealerts + rollback

Ask first

Peak traffic? Regional or global? Data residency? Strong consistency? Burst duration? Identity model? Compliance? Recovery targets? Budget and team skill?

State assumptions

“I will design for 10k peak RPS, p99 under 300 ms, zone redundancy, one-hour RTO and no loss of acknowledged writes.” Then make each choice defendable.

Quick drill

What is a weak answer to “design a notification platform”?

Starting with “use Service Bus and Functions” without clarifying delivery guarantees, ordering, retries, fan-out, user preferences, provider limits and replay.

02 / edge and API entry

Front door, policy and routing

Use Azure edge services to absorb traffic, terminate TLS, enforce policy and route only to healthy capacity.

DNSAzure DNS
Front Doorglobal HTTP edge
WAFedge policy
APIMAPI policy / quota
Backendprivate service

Front Door versus Traffic Manager

Front Door is global HTTP/HTTPS edge routing with acceleration and WAF integration. Traffic Manager is DNS-based traffic steering across endpoints and protocols.

Application Gateway versus Load Balancer

Application Gateway is regional Layer 7 routing. Azure Load Balancer is Layer 4. Choose based on path routing, TLS, WAF and protocol needs.

Interview diagram
Client → Azure Front Door + WAF
       → API Management
       → Application Gateway → service

03 / compute

Choose the right control plane

Azure offers several valid compute paths. Make the trade-off explicit: platform ownership, startup, control and workload shape.

NeedDefault candidateTrade-off
Simple web APIApp ServiceFast managed path; platform constraints and pricing model.
Container without cluster operationsContainer AppsManaged scale and revisions; less Kubernetes control.
Platform and custom schedulingAKSRich control; node, add-on and cluster operations.
Short event-driven workAzure FunctionsFast scale; runtime, concurrency and cold-start limits.
OS or network controlVM Scale SetsMaximum control; patching and capacity ownership.

Scale signals

Scale on HTTP concurrency, queue length, event lag or latency when those represent demand. CPU-only rules miss I/O and downstream saturation.

Backpressure

Use bounded concurrency, timeouts, circuit breakers, retry budgets and load shedding. Queueing is a contract, not an excuse to hide overload.

Managed compute still needs capacity design4 / 13

04 / data design

Model access patterns first

Azure data services expose different consistency, scale, query and operational contracts.

Azure SQL / SQL MI

Relational constraints, transactions and mature query semantics. Plan HA, read scale, connection pooling and migration strategy.

Cosmos DB

Partitioned global distribution with explicit partition-key, consistency and RU/s decisions. Hot partitions are a design failure.

Azure Cache for Redis

Reduce read latency and origin load. Define TTL, invalidation, stampede protection and behavior after cache loss.

Blob Storage

Durable object storage for files, artifacts and data lake patterns. Use lifecycle, immutability, encryption and replication deliberately.

Quick drill

Why can adding a Cosmos DB replica fail to fix a hot partition?

Replication does not repair a poor partition key. A single hot logical partition can still concentrate load; redesign access distribution and capacity assumptions.
Partition key and consistency before SKU5 / 13

05 / messaging and events

Make delivery semantics explicit

Service Bus, Event Grid and Event Hubs solve different problems. Choose from semantics, not naming.

APIvalidate + accept
Service Buscommands / queues
Workerbounded concurrency
DLQpoison messages
Event Gridevent routing

Service Bus

Durable enterprise messaging with queues, topics, subscriptions, sessions and dead-lettering. Consumers still need idempotency and bounded retries.

Event Grid versus Event Hubs

Event Grid is event notification and routing. Event Hubs is high-throughput streaming with partitions and consumer groups. Kafka workloads may fit Event Hubs for Kafka.

Pattern
API → Service Bus → worker → database
                    ↘ failures → DLQ → replay workflow

06 / high availability and DR

Name the failure domain

Zone redundancy, paired regions and geo-replication address different failures and impose different consistency costs.

PatternUse whenCost / risk
Availability ZonesSurvive local datacenter or zone failure.Regional services and dependencies remain a boundary.
Backup and restoreRTO permits minutes or hours.Cheaper; restore correctness and data transfer need tests.
Paired-region standbyNeed regional recovery with controlled cost.Capacity, replication and failover procedure.
Active-activeVery low RTO and global demand.Conflict resolution, routing and operations complexity.

Azure tools

Azure Backup, Site Recovery, SQL geo-replication, Cosmos DB global distribution, Storage replication and Front Door health-based routing.

RTO / RPO

Define how much data can be lost and how fast service returns. Include DNS, warm capacity, promotion, key replication and operator steps.

07 / identity and security

Use Microsoft Entra ID as the spine

Human access, workload identity, secrets and policy should be separate but observable.

Identity chain

Human → Entra ID group / PIM role → Azure RBAC. Workload → managed identity → scoped role assignment → resource. Secrets → Key Vault with private access and rotation.

Useful check
az role assignment list \
  --assignee OBJECT_ID --all

Boundary controls

Entra IDAzure RBACManaged IdentityKey VaultPrivate LinkNSGAzure Policy

Use policy-as-code, Defender for Cloud, activity logs and resource locks where appropriate.

Quick drill

A web app needs one Key Vault secret. Would you store a client secret in an app setting?

No. Use a managed identity with a narrow Key Vault data-plane permission, private networking where required, audit logging and rotation without redeploying credentials.

08 / networking

Know the VNet path

Azure networking interviews test whether you can reason across address space, routing, security and private service access.

VNetaddress space
Subnetdelegation / NSG
RouteUDR / firewall
Private Linkservice boundary
Workloadapp / data

Private access

Private Endpoints and Private Link keep supported PaaS traffic off public ingress. Private DNS zones must resolve names to private addresses consistently.

Security layers

NSGs filter subnet/NIC traffic. Azure Firewall centralizes inspection and egress policy. DDoS Protection and WAF address different layers and threats.

09 / observability

Azure Monitor is a system, not a checkbox

Connect metrics, logs, traces, resource health and deployment events to the user-facing SLO.

SLIAvailability, latency, freshness, correctness
MTTDUseful alert time
MTTRTime until impact ends

Signals

Azure Monitor metrics, Log Analytics, Application Insights, distributed tracing, Activity Log and Service Health. Add deployment markers and business outcomes.

Alert quality

Alert on error rate, p95/p99 latency, queue age, dependency failures, quota exhaustion, node pressure and data freshness. Avoid pages for harmless noise.

A healthy resource metric does not prove a healthy user journey. Correlate from edge to dependency.
Observe symptoms, preserve causal context10 / 13

10 / LLM platform pattern

Azure OpenAI gateway under load

LLM capacity is measured in tokens, concurrency, quota, deployment limits and latency—not merely VM size.

Clientauth + tenant
APIMquota + policy
Azure OpenAImodel deployment
Monitortokens / latency
Fallbackdegrade safely

Reliability controls

Per-deployment quotas, bounded retries with jitter, circuit breakers, concurrency limits, model fallback, streaming and prompt-size controls.

Metrics

429s, requests, prompt/completion tokens, time to first token, inter-token latency, end-to-end latency, content filter outcomes and cost.

Incident drill

Azure OpenAI returns 429s and gateway latency rises. What hidden amplifier do you inspect first?

Immediate retries and unbounded concurrency. Bound retries, add jitter, limit tokens and concurrency, route across approved deployments and queue non-interactive work.

12 / close

The Azure design checklist

Finish with a system that can be built, secured, observed, scaled and recovered by a real team.

Architecture

Requirements, estimates, request flow, data model, edge, compute, messaging, identity, network, zone/region strategy and consistency.

Operations

SLOs, dashboards, alerts, deployment strategy, rollback, backups, restore test, quotas, cost, ownership and compliance evidence.

A senior answer does not say “Azure is resilient.” It says which failure is covered, how traffic moves, what data can be lost, how recovery starts and how you prove it.
